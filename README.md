# نظام المعدات والخدمات الزراعية (زراعة)

نموذج أولي يعمل فعلياً (PHP + تخزين JSON) لمنصة تربط المزارعين بالموردين وفنيي الصيانة والخبراء الزراعيين، حسب وثيقة متطلبات النظام (SRS).

## التشغيل محلياً (XAMPP)

1. شغّل Apache من لوحة XAMPP (لا حاجة لـ MySQL — التخزين الآن عبر ملفات JSON).
2. انسخ هذا المجلد إلى `C:\xampp\htdocs\مشروع ندوة`.
3. افتح المتصفح على `http://localhost/مشروع ندوة/`.

## ما تم إصلاحه وتحسينه

- **الاتجاه والشكل العام:** توحيد كل الصفحات على `lang="ar" dir="rtl"` وخط Tajawal، وإصلاح محاذاة الجداول والقوائم التي كانت تظهر بشكل معكوس (يسار بدل يمين).
- **تسجيل الدخول والصلاحيات:** كل لوحة تحكم أصبحت محمية فعلياً (`requireRole`) — لا يمكن فتحها إلا بعد تسجيل الدخول وبالدور الصحيح، وأي شخص يحاول الدخول لدور غير دوره يُعاد توجيهه للوحته الخاصة.
- **زر تسجيل الخروج:** كان يشير خطأً إلى صفحة الدخول بدل تسجيل الخروج الفعلي؛ تم إصلاحه في كل الصفحات عبر رأس صفحة موحّد.
- **البحث الحقيقي:** مربعات البحث في الصفحة الرئيسية ولوحة المزارع كانت لا تُفعّل أي فلترة فعلية (بيانات تجريبية ثابتة)؛ أصبحت الآن تُرجع نتائج حقيقية حسب الاسم/الوصف/الفئة.
- **حجز الاستشارات:** كانت شاشة "ملخص الحجز" ثابتة دائماً بنفس الاسم والرسوم بغض النظر عن اختيارك، ولم يكن إرسال النموذج يُنشئ أي حجز فعلي. أصبح الحجز خطوتين: اختيار الخبير، ثم اختيار موعد ونوع استشارة حقيقيين من قائمته، مع احتساب الرسوم الصحيحة وحفظ الحجز وربطه بحساب المزارع، وإزالة الموعد من قائمة الأوقات المتاحة بعد حجزه.
- **طلبات الصيانة:** المزارع يختار فنياً حقيقياً ويرسل طلباً فعلياً؛ الفني يرى طلباته فقط ويمكنه قبولها أو رفضها أو تحديث حالتها حتى الإكمال.
- **لوحة المورد:** كانت للعرض فقط بدون أي إمكانية فعلية للإضافة أو التعديل؛ أصبح بإمكان المورد إضافة منتجات جديدة، تعديل حالة التوفر، وحذف المنتجات.
- **لوحة الخبير الزراعي:** أصبح بإمكان الخبير تعديل بياناته المهنية ورسومه، وإدارة قائمة المواعيد المتاحة (إضافة/حذف)، ومتابعة حجوزاته وتأكيد إتمامها أو إلغائها.
- **لوحة المدير:** الإحصائيات كانت أرقاماً وهمية ثابتة؛ أصبحت محسوبة فعلياً من البيانات الحالية (عدد المستخدمين لكل دور، الحجوزات، الإيرادات المؤكدة)، مع إمكانية إغلاق طلب صيانة عالق أو إلغاء حجز من قِبل الإدارة.
- **رسائل واضحة:** تمت إضافة نظام رسائل تنبيه (نجاح/خطأ) بعد كل عملية إرسال نموذج بدل الصمت أو إعادة التوجيه غير المفسَّرة.

## بنية التخزين

جميع البيانات تُحفظ كملفات JSON داخل `storage/` وتُنشأ تلقائياً عند أول استخدام:

- `storage/users.json` — الحسابات (تتضمن أيضاً بيانات الملف المهني للمورد/الفني/الخبير).
- `storage/products.json` — المعدات والمستلزمات.
- `storage/service_requests.json` — طلبات الصيانة.
- `storage/appointments.json` — حجوزات الاستشارات.

## قاعدة البيانات (للإصدار الإنتاجي)

ملف `schema/mysql_schema.sql` يوثّق تصميم قاعدة بيانات MySQL الكامل المخطط له للإصدار الإنتاجي القائم على خادم حقيقي؛ النموذج الحالي يستخدم ملفات JSON فقط ليعمل مباشرة دون إعداد قاعدة بيانات.
